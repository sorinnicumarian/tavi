The LTL checker examines if the execution traces satisfy the safety LTLf rules. We have decided to use LTLf instead of LTL, since we are dealing
with finite-step executions. The project utilizes the \texttt{flloat} library to perform the LTLf checking of the rules against the traces.

Before checking the trace against the rule, the trace is transformed into boolean predicates suitable for LTLf rule checking. We express
the traces in the shape of a dictionary, where the existence of a predicate in the original trace would transform to a key-value pair in the
dictionary where the key holds the predicate value and the value set to "True". The LTL rule templates are instantiated by the objects 
belonging to each task step, resulting in concrete LTL rules used for checking the traces directly.

We define a safety violation to be the steps in the task which together lead to the LTLf formula being set to "False". In the case
where there is a violation, we identify the earliest step in a task which leads to the violation. Then, the rule checker outputs the 
rule which is violated, the formula related to the rule, the name of the action leading to the violation, and the step identifier.

This project allows online checking deviating from traditional offline checkers. We do not wait for the task to finish in order to
report the violation. Instead, when a step is executed, it is traced, translated into predicates, appended to the task dictionary used for direct checking,
and then verified by the LTLf checker. When a violation occurs, the program raises the \texttt{SafetyViolation} exception. Then, the information
corresponding to the violation is logged in an error log and the current task is immediately terminated moving on to the next one.
